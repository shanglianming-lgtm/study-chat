# 书房 Chat · M1 本地聊天闭环

## 当前书房场景

### 实时光线与天气

窗外、窗边日光与灯光共用本机时钟，运行中每秒检查，清晨与傍晚平滑过渡。夜间不再留有日光斑，绿色台灯从灯罩下方照亮桌面，落地灯随之渐亮。没有定位时，采用本地 05:30–08:00 日出、17:00–19:30 日落的近似周期（不是天文日出日落）。

默认通过 `https://ipapi.co/json/` 获取 IP 大致位置，再将经纬度四舍五入到 0.1 度请求 [Open-Meteo](https://open-meteo.com/) 当前云量与天气代码；不调用 GPS、不保存 IP 或坐标。天气每 30 分钟刷新，阴天削弱直射光，雨、雪和雾出现在窗外，室内灯光按实际环境亮度渐亮。每次查询 8 秒超时；失败保留不超过 1 小时的最近天气，之后回退晴天，不影响本机时钟。网络恢复或重新显示窗口时检查更新。

管理书「书目」里的「窗景跟随当地天气」可随时关闭联网查询（立即中止请求并恢复晴天），开关保存在本机。IP 位置受 VPN 影响，可能不是实际城市。天气数据按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 使用；免费接口用于非商业原型。后续可将天气查询替换为 WeatherKit，但 Apple 签名私钥不能放入前端。Windows 原生运行允许的联网域名仅增加上述两个天气相关域名。

点击门扇进入书房，越过门后门会自行合上。WASD 行走，脚步会随起停和地毯变化。光标在画面内部移动时视线会略迟跟随。停在左右外缘会持续转身，可以转过整圈，移回中央会在新朝向停稳。上下外缘可抬头或低头。拖动可直接转头，系统减弱动态时关闭自动跟随。按 Esc 可暂停或静音。物件在光标经过时出现轮廓，也可以用 Tab 选择、Enter 操作。

书柜中层左格的绿布烫金封面可用来添书。点它后题写书名，回车后纸张会聚拢、合封并飞入书格。点不同的书脊可以取阅对应的一册，持书时点击书桌或椅子落座，点击书柜即可归还。中层右格的墨水屏管理书坐在独立托座上，取用时会先抽离层板。窗户仍可开合，日景与暮景随本机时间切换。

运行时模型位于 `public/assets/models/`。桌面播放器作为陈设。白裙角色是用户的第一人称化身，随玩家行走、转身和落座。取书时先翻腕招手，书从架上滑出，几粒纸尘随书脊散开。书沿浅弧减速，在右手掌心正上方略微侧倾，能同时看见布面、书脊和纸边。移动光标时手先动，书随后加速追上，收势时封面轻颤合拢。走动和转身也会带动书。书在架上、掌上和桌面保持同一开本，落座时在桌面展开，还书时滑回书挡之间。下方保留原 M1 交付记录。


落座后打开当前对话书。左页的 Memory、Profile 摘要可点开原文。右页章名固定，问答正文独立滚动。停在底部会跟随新字，上翻后保留阅读位置。光标移到右页下方或用 Tab 聚焦输入区，可附加文件、选择本书可用的模型和推理强度。Enter 发送，Shift+Enter 换行。强度包括供应商默认、Light、Low、Medium、High、Max。默认档省略模型请求中的强度字段。

点击模型回答首句查看本轮可公开的推理摘要、资料、Skill 和调用记录。点问题或回答的末句唤出复制、删除和重试，删除以一轮问答为单位，原位可撤销。输入与输出文件按 [n] 引用。点击纸面空白或右键可打开书内菜单，进入卷首与样章、导出对话或切换书目。窄屏可点左右页边或用左右方向键切换记忆页和对话页。

书架上的墨水屏设备 **Library Register** 是独立的管理书，书内菜单也有入口。在「提供商」填入兼容 Chat Completions 的服务地址，离开地址栏会请求模型目录。可补录模型 ID 或手动点「测试响应」发送一条短请求。在「书目」里设置每本书的可用模型、三个模型角色和两段小模型提示词。总结模型可重写左页摘要，第一轮结束后拟定章名。决策模型选择资料，作答使用输入框选定的模型。桌面版 Key 按地址保存到系统凭据库，网页版 Key 仅在当前网页会话使用，网页直连需服务商允许跨域。内置 Study 是独立的本地演示提供商。

桌面版首次打开会从旧 SQLite 会话接入历史、草稿和提供商配置。新版书库按版本保存到同一数据库，附件保存在本机 WebView 的 IndexedDB。网页书库与文件使用当前站点的 IndexedDB。

本地分支 `local/m1-chat-loop` 基于 Devin PR #1 的 `c75b4d4`。保留书页、速记与房间，新增原生 OpenAI-compatible SSE、系统凭据、SQLite 恢复和 Markdown 导出。当前网页版与桌面版均可接入兼容供应商。

原始 M1 源码包的启动说明和历史验证记录见 [Windows 解压、启动与验收步骤](docs/M1-Windows.md)。

# 书房 Chat

一间安静的书房，一本与你一起写成的书。Tauri 2 + React + Vite + TypeScript 的 Windows 桌面交互原型。**不部署、不调用真实模型、无需 API key。**

## Windows 准备

- Windows 10 / 11，推荐 PowerShell 7。
- [Node.js 22 LTS](https://nodejs.org/) 和 pnpm 10.11（可运行 `npm install -g pnpm@10.11.0`）。
- **仅桌面入口需要**：[Visual Studio 2022 Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，选择「使用 C++ 的桌面开发」，安装 MSVC 和 Windows 10/11 SDK。必须等待安装器显示安装完成，再打开新 PowerShell；可使用「Developer PowerShell for VS 2022」。否则可能误用 Git 的 `link.exe`，导致 Rust 链接失败。
- **仅桌面入口需要**：[Rust stable / rustup](https://www.rust-lang.org/tools/install)，使用默认的 `stable-msvc` 工具链。
- **仅桌面入口需要**：[Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。Windows 11 通常已内置，仍需确认可用。
- 安装工具链后重新打开 PowerShell，确保 `node --version`、`pnpm --version`、`rustc --version` 可用。详见 [Tauri 官方 Windows 依赖说明](https://v2.tauri.app/start/prerequisites/#windows)。

```powershell
git clone https://github.com/shanglianming-lgtm/study-chat.git
Set-Location study-chat
# 切到本 PR 的分支后：
pnpm install --frozen-lockfile
```

### 可选入口一：网页预览

```powershell
pnpm dev
```

浏览器访问终端显示的 `http://localhost:1420`。不需要 Rust、Visual Studio 或 WebView2 开发工具。与桌面入口使用同一套前端，不是单独的演示页面。

### 可选入口二：Windows 独立桌面窗口

```powershell
pnpm tauri dev
```

此命令自动启动 Vite，然后打开独立窗口。**不要同时运行另一个 `pnpm dev`**，两者使用同一个固定端口 1420。首次 Rust 编译需要下载依赖，耗时较长。此版本不生成安装包，`bundle.active` 为 `false`。

## 如何试用

场景四周不再常驻显示应用标题、地点／桌前说明、步骤目标或底部键位／阅读提示；只有靠近并面对书架或书桌时才显示 E 交互卡。进入／暂停界面的操作说明、鼠标视角恢复与辅助操作按钮、书内导航和写作控件保留。装订／过程附页的状态仍向屏幕阅读器播报，不再额外挂在书页下方。

书上方的整条深色工具栏也已移除；「目录」「速记纸／回到书页」「合书」以小字排在纸页底部。书页模式在桌面宽窗保持左右双页与书沟，宽度小于 860px 时使用单页；速记本来就是一张连续纸，页脚标为「Field notes · 连续纸」，不是把书的两面合并。

1. 点击「走进书房」，从房间内部以第一人称探索。WASD 行走，鼠标转头；方向键上／下前后走、左／右转头。Esc 释放鼠标并暂停，再点击继续。
2. 沿通道走到后墙书架，面对《与自己的漫长对话》，出现提示后按 E 取下书。书会拿在手中，不能从远处直接取书。
3. 走到右侧窗边书桌，出现提示后按 E 坐下、摊开书。英文出版结构依次为 Half Title、Title Page、Copyright & Imprint、Contents、Preface 和 About the Reader，随后是中文正文；前置页用小写罗马页码，正文从 1 起算。方向键、页角或底部按钮翻页，窄窗自动使用单页。
4. 摊开书后焦点在合书按钮；点击红色「续写」书签，到书页内写下问题。Enter 发送，Shift+Enter 换行；中文输入法选词的 Enter 不发送。草稿与每轮 Question / Response 都排在纸页中，不使用书外聊天框。
5. 模拟回应逐步写入书中，按纸面容量续页；生成时跟随最新页，手动翻阅后不抢回位置。纸页底部可随时「停笔并装订」，现有部分仍装订。默认折叠的 Notes & sources 展开为可翻阅的过程附页，显示推理摘要与工具调用**示例**，不代表隐藏思维链、真实模型请求或实际执行工具。
6. 完成后自动跳到新回答开头。在「目录」中点击该轮提问或回答可返回，不依赖写死页码。
7. 纸页底部的「速记纸／回到书页」切换两种模式，共享对话、输入草稿、模型和推理强度，速记也是房间中摊开的纸页。版权页可选择示例模型与推理强度、编辑提供商信息；扉页可编辑作者、出版者、版次，Preface / About the Reader 可改写记忆与 profile 示例。字段平时与纸面融为一体，悬停或聚焦时呈凹陷状态；设置只影响模拟标签，不调用模型。
8. 点击纸页底部「合书」或按 Esc，拿着书回到房间；原先使用鼠标捕获时，起身后会尝试恢复鼠标视角。若浏览器拒绝自动捕获，可直接点击画面或明显的「点击恢复鼠标视角」按钮，无需先按 Esc；主动选择的不锁定模式则保持拖动转头。走回书架，面对原位按 E 归还；本次窗口内重新取书可继续阅读。

不想捕获鼠标时，可在进入／暂停界面选择「不锁定鼠标」，按住画面拖动转头；「辅助操作」提供屏幕行走与转头按钮，窄屏／触屏默认显示。交互按钮也可以用 Tab 聚焦、Enter 激活；辅助方向按钮按住 Enter／空格行走。切出应用会暂停，避免失焦后持续行走。

## 实现边界

- 书房是全窗口的 Three.js 第一人称场景，不是可环绕缩放的模型展示：绿色沙发和落地灯在左侧，木质书架在后墙，窗帘、大窗和书桌／台灯在右侧。沙发采用本地打包的 Poly Haven CC0 glTF，其余家具、植物和书为本地几何体；橡木、地板、亚麻 PBR 贴图与全景环境也随应用打包，不运行时访问资源 CDN。[资源来源、许可与修改](public/assets/ASSETS.md)。
- 人物视点有墙体和家具碰撞，取书／归书／坐下需要靠近并面对目标。同一本带铰链封面的 3D 书在书架、手中、桌面间移动；手持书使用独立深度层，避免靠墙时被遮住。坐下后保持同一房间和桌前镜头，窗、灯和木桌持续可见，书页与书写纸放在前景，不切换为独立网页。文字仍用可选择、可访问的 HTML 排版，原有分页、对话和速记保留。
- 可交互提示随书脊／桌面在屏幕中的投影移动，不再固定放在底部。静态房间缓存阴影；持续慢帧时只降低三维场景分辨率，HTML 文字和阅读器保持原始清晰度。软件渲染仍不等于真实 GPU 性能。
- 尊重 `prefers-reduced-motion`：取书、坐下、起身和归还的自动过渡直接切换；主动行走和转头仍由用户控制。无 WebGL 时提供直接取书入口，不阻断阅读和对话。
- 窗户有真正的几何开口，窗框与家具投影落在地面；宽面窗光、中性环境反射与两盏没有硬距离截止的暖灯分层。墙角遮蔽和地毯上的家具／腿脚接触遮蔽预烘焙到顶点，不依赖逐帧 AO。灯罩与台灯灯管有发光材质。HDR 负责材质照明，独立曝光的全景负责窗外景物，避免窗外过曝。木材与织物使用颜色、法线和粗糙度贴图。静态家具按材质合批，异步替换的沙发与窗景不合批，装饰书共用书脊文字图集；不使用逐帧后处理，也不声称实现了路径追踪或实时全局光照。
- 识别到 SwiftShader、llvmpipe、Microsoft Basic Render Driver／WARP 等软件后端时，自动保留模型、颜色贴图、窗景、太阳／窗框投影、台灯与落地灯、预烘焙接触遮蔽，但用天空填光近似替代 LTC 面光和 HDR 反射，省去逐像素法线／粗糙度采样。硬件路径仍保留完整 PBR；软件模式不是同等画质或真实 GPU 性能的承诺。
- 软件模式还省去亚像素书脊饰带的倒角和 4× MSAA，保留较大家具倒角与 PCF 柔化日光阴影；地毯接触遮蔽使用较低网格密度。静态合批恢复顶点索引，避免每个三角形角点重复变换，法线／UV／顶点色接缝不合并。开发模式可用 `?renderMode=full` 强制检查完整 PBR 路径；在软件后端强制此模式不代表真实 GPU 验证。
- 软件模式仅在走动、转头与书／坐立过渡期间把三维缓冲区降到每轴 40%；最后一次移动约 250ms 后恢复原始 DPR（上限 1.5），按需补画清晰静帧。HUD、书页和输入框始终是原生 HTML 清晰度；移动中房间会更软，这是明确的分辨率取舍，不是同缓冲区下的着色提速。完整硬件路径不启用此策略。
- 暖白纸色、本地打包的 Noto Serif SC（宋体回退）、镜像边距与实际页码。按真实 DOM 测量分页；长段落和代码可跨页，片段保留链接与内联标记。窗口或字体就绪时重新排版，导航目标保留章节 / 消息 ID。
- 布面封壳、书沟、纸纹、随进度变化的左右纸叠模拟装订厚度；翻动的是带正反内容、分段弯折和阴影的 CSS 3D 纸叶，而不是整页淡入淡出。减弱动态效果时直接换页。它是视觉近似，不是纸张物理仿真。正文、实时回应、目录与展开的过程附页按容量续页，不以单页滚动代替分页；超长草稿和元数据仍是可滚动的文本编辑字段。速记保留连续记录形式。所有编辑和对话仍只保留在本窗口内。
- Markdown 支持段落、标题、列表、代码、链接；DOMPurify 限制标签和属性。不加载 Markdown 图片，防止粘贴内容触发远程资源。流式未闭合围栏按纯文本显示。
- 停笔装订补齐可判定的强调与行内代码格式。未闭合的显式链接排印为「标签（已写出的网址片段）」，不生成点击目标、不猜测目的地址，并保留后文；完整链接和代码中的字面语法不改写。编辑框仍保留源 Markdown。含链接或行内代码的段落自然左齐，避免长标记拉伸中文字距；中文正文与停笔说明保持正体，不合成斜体。
- 裸链接仍受 GFM 识别边界限制：`https://例子.中国/路径` 这样的纯中文域名可能只显示为文字。可改写为显式 Markdown 链接，例如 `[中文来源](https://例子.中国/路径)`；带 `www.` 的对应地址可自动识别。未扩展通用裸链接识别器。
- 仅主动点击 HTTP(S) 正文链接时打开浏览器；Tauri 使用受限 opener capability，网页使用新标签页。不会自动访问输入的网址、抓取网页或读取浏览器登录态。「演示」来源卡不是检索结果。
- 所有文字、对话和草稿只在内存中，刷新 / 关闭会重置；不使用数据库、localStorage、登录、记忆、真实模型、天气、音乐或卷纸物理。
- 中文字体随前端一起打包，不依赖 Google Fonts 或其他 CDN。首次安装依赖仍需网络。

### 家具与道具重建

- 沙发改为 CC0 实体资产，保留弧面软垫、雕花木框和腿脚，面料贴图调为鼠尾草绿；椅垫和窗帘补入亚麻织物微表面。新沙发保持原导航占地，不改变行走碰撞。
